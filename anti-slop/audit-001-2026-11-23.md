# antislop audit 001 (2026-11-23)

Scope: the whole Jekyll site (Cayman theme + `assets/css/style.scss` + `_includes/head-custom.html`) and all 10 week pages.

How it was checked:
- Ruby isn't installed, so the site couldn't be built locally. Checked the live GitHub Pages site instead.
- Headless Edge screenshots at 1366px desktop width, plus the home page and weeks 2, 5, 8 and 10 rendered inside real 390px iframes. Headless Edge won't size its window below 492px, so a plain "390px window" screenshot isn't a real phone width.
- Every text/background pair in both themes went through the antislop contrast checker.
- Code inspection of the CSS, the include and the week Markdown.
- Not done: a manual keyboard click-through in a real browser.

Priority follows the rule tier: Hard Gate = HIGH, Purpose-Gate = MEDIUM, Quality Lock = LOW. **Ugly** marks the findings that do the most to make the site look worse.

Current read of the site: personal coursework portfolio for classmates and instructors, warm-paper "drafting studio" language, dial ENERGY 2 / RHYTHM 1 / MOTION 1.

---

## HIGH (Hard Gate)

**1. Dark mode: white text on coral fails contrast** *(R-25)*
`#fff` on `#e2725c` is 3.09:1 (needs 4.5:1). It hits three places:
- the "View on GitHub" button hover (`style.scss:167-173`)
- the week 2 contraband `summary:hover` (`style.scss:524-527`)
- `::selection` (`style.scss:104-107`)

Light mode passes (5.52:1) because the coral is darker there.

**2. In dark mode, color alone marks links** *(R-25, WCAG 1.4.1)*
- Dark mode: the underline is `#38321f` on `#201d15`, only 1.32:1, so it's effectively invisible. Link vs body text is 2.05:1.
- Light mode: underline 1.74:1, link vs body text 2.30:1.

A link needs 3:1 against the text around it, or a visible non-color cue. See `style.scss:238-245`.

**3. On phones, the theme toggle covers text** *(R-03)* · Ugly
The fixed toggle at the bottom right sits on top of body copy. At 390px it covers text on weeks 8 and 10. See `style.scss:398-417`.

**4. The theme toggle's name contradicts its state** *(R-39)*
The label flips between "Switch to light/dark mode" while `aria-pressed` is also set. A screen reader hears "Switch to light mode, toggle button, pressed". Fix with either a stable label ("Dark mode") plus `aria-pressed`, or a changing label with no `aria-pressed`. See `_includes/head-custom.html:31-37`.

**5. No site navigation landmark** *(R-39, R-32)*
- The header title is plain text, not a link home.
- The only way back is "← All weeks" inside the content.
- There's no previous/next between weeks, no `<nav>` and no skip link.

This comes from Cayman's stock layout. The fix is a `_layouts/default.html` override.

**6. Mermaid loads on every page and blocks rendering** *(R-40)*
The full Mermaid bundle is a synchronous `<script>` in `<head>` on all 11 pages, but only week 3 uses a mermaid block. Every page waits on a jsdelivr request it doesn't need. See `_includes/head-custom.html:141`.

**7. Images have no dimensions, so the layout shifts** *(R-40)*
That's 65 Markdown images, plus the raw `<img>`/`<video>` tags in weeks 2 and 10, all with no `width`/`height`. The text jumps down as each image arrives. Kramdown accepts `{: width="..." height="..."}` after an image.

## MEDIUM (Purpose-Gate: technique allowed, but no reason tied to this site)

**8. Background grids** *(R-07)* · Ugly
There's a dot grid on the whole page (`style.scss:97-98`) and blueprint lines in the header (`style.scss:119-120`). The comment calls it "drafting paper", but it's the stock "make it look technical" texture and doesn't connect to any of the projects.

**9. Teal glow orb in the header** *(R-01)*
A radial teal glow sits in the top-right of every header (`style.scss:118`). It's a classic default treatment and does no hierarchy work.

**10. Space Grotesk is borrowed from one project** *(R-06)* · Ugly
You picked it in week 2 for the fictional surveillance client, for its "futuristic, dystopian tech vibe". That's a good reason for the client, but a poor one for your own portfolio. Two side effects:
- week 2's type specimen no longer stands out from the site around it
- the whole site wears ■lock's identity

It's also one of the most common AI-default sans fonts.

**11. Uppercase labels with wide letter-spacing** *(R-06)*
- `.btn` (0.14em)
- table headers (0.09em)
- `.flow` labels: monospace, 0.12em, shrinking to about 9px on phones
- `.contraband > summary` (0.16em monospace)
- `.stamp`, `.scale-check` and `.palette .hex`

The week 2 contraband and stamp pieces belong to that project's fiction and could keep it, scoped to week 2.

**12. Hard offset shadows on everything** *(R-12)* · Ugly
The main card, every image, the toggle, the flow images, the week 8 example cells, the lightbox and the button hover all carry a hard offset shadow (most at 10px). When everything floats, nothing stands out, and images look like stacked stickers instead of documentation.

**13. Every section heading stacks four markers** *(R-01, R-31)* · Ugly
Each h2 gets:
- a dashed rust `hr` above it
- a rust square
- its emoji
- an underline rule

Separately, the page title gets a rust bar under it, and the header's 4px rust bottom border pokes out on both sides of the content card at every width. The emoji stays (it's intentional). The rest could be cut down to one marker.

**14. Colored left stripes** *(R-01)*
- `pre` has a 3px teal stripe that's pure decoration.
- `blockquote` has a 4px teal stripe that does mean "quote", but the ⚠️ asides and the quoted SMART goal look identical. Two different meanings share one treatment.

## LOW (Quality Locks)

**15. Two accent colors, both everywhere** *(R-29; one deliberate accent)*
- Rust: links, h2 squares, rules, header border, title bar, toggle shadow, selection.
- Teal: h3s, inline code, table numbers, stripes, header glow.

Neither one reads as *the* accent.

**16. Generic identity** *(R-20)* · Ugly
The structure is Cayman's with paint on top: big header, "View on GitHub" button, floating card, "generated by GitHub Pages" footer. The home page is one table. Swap the title and it could be any repo. You already have the material for something specific in each week's `img/` folder.

**17. Template footer and repeated GitHub links** *(C-3, R-05)*
The home page links to GitHub three times:
- the header button, which is on every page
- "Source on GitHub" in the content
- the footer's "...is maintained by dolphinswarm"

The footer also has "This page was generated by GitHub Pages", which is Cayman filler.

**18. The home table gets cramped on phones** *(R-05, C-4)*
At 390px the three columns squeeze Notes to a few words per line, so rows run 5-6 lines tall. Week 10's note breaks before ", a plan". The list of weeks should stack on narrow screens.

**19. Image captions sit beside the image** *(C-4)* · Ugly
An image followed by an `_italic caption_` line lands in the same paragraph. On week 11 the caption starts beside the bottom of the map and wraps underneath it. The same pattern is used on every page. One CSS rule (`p > img + em { display: block }`) fixes it without touching content.

**20. Tables** *(C-4, R-31)* · Ugly
- In dark mode the header row is a cream `#f0eadb` slab, the brightest thing on the page.
- Tables with blank headers, like week 10's SMART table, render an empty cream bar.
- The home table's "week number" styling (monospace + bold + teal + nowrap) applies to the first column of *every* table. Week 5's tool names come out in teal monospace.
